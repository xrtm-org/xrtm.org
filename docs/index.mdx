# Choose the right XRTM docs lane

XRTM is **AI for event forecasting**. The docs are organized into explicit lanes
so released workflows, near-term unreleased work, package references, and
governance do not blur together.

> `xrtm.org` is the presentation layer for the ecosystem. Product behavior and
> released run-artifact contracts live in
> [`xrtm-org/xrtm`](https://github.com/xrtm-org/xrtm), package APIs and source
> examples live in their owning repos, and schema/policy truth lives in
> [`xrtm-org/governance`](https://github.com/xrtm-org/governance).

## Quick chooser

| If you need... | Start here | Status | Canonical owner |
| --- | --- | --- | --- |
| the shortest honest first success | [Getting started](/docs/getting-started) | Released | `xrtm` repo + published `xrtm==0.3.0` package |
| released compare/export/monitor workflows | [Released user path](#released-user-path) | Released | `xrtm` repo |
| branch-only conveniences that are real but unreleased | [Next release track](/docs/next-release) | Explicitly unreleased | `xrtm/docs/next-release-feature-track.md` + governance policy |
| package boundaries, APIs, and source examples | [Developer & package reference](#developer--package-reference) | Repo-map summary | owning package repo |
| binding schemas, feature labeling rules, or release policy | [Governance & standard](#governance--standard) | Authoritative | `governance` repo |
| longer-horizon or experimental ideas | [Roadmap](/docs/roadmap) | Future-facing | roadmap + owning repos |

Use these pages when you want the public `xrtm==0.3.0` surface today:

- [Getting started](/docs/getting-started): provider-free first success on the released package
